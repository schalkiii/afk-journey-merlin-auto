# 实机开发与调试方法学

本文只讲**怎么在这个项目上开发、调试、验证**：怎么在不动用户鼠标的前提下跑真实游戏、
怎么判定「真的进去了 / 真的领到了」、怎么收尾。模板本身的采集与标定规则见
[TEMPLATE-AUTHORING.md](TEMPLATE-AUTHORING.md)；行为约束见根目录 `CLAUDE.md`。

## 1. 前置条件（先确认，否则所有现象都会误诊）

- **点击器存活**：`common.clicker_alive()`。游戏《剑与远征：启程》以**管理员**运行，
  未提权进程的 `SendInput` / `PostMessage` / `PrintWindow` 会被 UIPI 拦截（实测
  PrintWindow ok=0、PostMessage=0）。点击走文件 IPC：Python 写
  `shared/target_coord.txt`（**整屏绝对坐标**）→ 提权的 `click_from_file.exe` 消费并注入。
  点击器自己退出后所有点击静默落空，表现是「界面连续多轮无变化」——先查它，再查逻辑。
- **后台点击做不了，别在这上面浪费时间**：实测对本作 Unity 客户端，`PostMessage` /
  `SendMessage`（含 `WM_ACTIVATE` / `WM_SETFOCUS` 预热）都返回成功但界面毫无变化；
  给窗口加 `WS_EX_NOACTIVATE` 后在非前台状态发真实点击也不生效。它只接受真实前台输入，
  所以「完全不抢鼠标」不可实现；能做的只有每次点击后把光标放回原处
  （`common.send_coord` 的默认行为），窗口激活瞬间无法避免。
- **截图通路**：默认 Windows Graphics Capture（`windows-capture`），能截被遮挡/提权窗口；
  不可用时回退普通屏幕截图。截图坐标系始终是**全屏**，`find_center*` 返回值也是全屏坐标。
- **客户区必须 1600×900**：`game_client_region()` 每次调用都重新校验；不是这个尺寸
  整套模板与偏移全部失效，GUI 启动任务时会打警告。RDP 断连/锁屏时系统停止渲染，
  后台截图拿不到新帧——保持会话连接。

## 2. 怎么发起一次实跑（不碰用户鼠标）

用户明确不要用桌面自动化挪鼠标，所以实跑一律走进程，两种形态：

1. **走 GUI（验证真实用户路径）**：临时脚本实例化 `GameBotGUI` →
   `select_script(idx)` → `root.after(2500, app.run_single_script)` →
   `root.after(120, app._drain_log_queue)` → `mainloop()`。
2. **直调流程（验证单个状态机）**：临时脚本 `import flow_push; flow_push.main(...)`。

共同纪律：

- 用 `pwsh -NoProfile -Command "Start-Process ... -PassThru | Select-Object -ExpandProperty Id"`
  **分离启动并拿 PID**，不要在前台阻塞等待。
- runner 里把 stdout/stderr tee 到 `%TEMP%` 的日志文件并**每行 flush**，
  之后用短命令轮询 `tail -c`；不要 `sleep` 很久再一次性读。
- 结束用 `taskkill //F //PID <pid> //T`（连子进程树），并确认没有孤儿 `python` 留下。
  判别归属看进程 `StartTime`：本轮的 PID 与用户长期存在的进程要分得清。
- 临时脚本与截图**写在 `%TEMP%`，不落在仓库根目录**；用完即删。

## 3. 坐标纪律

- `send_coord` / `click_position` 收的是**整屏绝对坐标**。调试脚本若按客户区坐标点
  （如 `x=100, y=35`）必须加 `game_client_region()` 原点再传，否则点到别处——
  本轮就因这个 bug 把「点击没生效」误判成游戏问题。
- 客户区固定 1600×900 时，允许「固定点位点击」，但**必须带进入校验**（见 §4），
  且把点位写成带注释的常量（如 `PATA_CARD_POS = (625, 700)`），不要散落魔法数。
  点位只能来自实机截图实测：右侧 HUD 竖排 `(1550,610)` 看起来像「月桂之旅」入口，
  实测点完只落在主界面，真入口在菜单第二行第 4 张卡片 `LAUREL_MENU_POS = (905, 625)`。
- **模板一直等不到时，先怀疑遮挡而不是阈值**：玩法目录第三行卡片的卡名被底部页签栏压住，
  同一张 `pata.png` 无论阈值调到多低都匹配不到（实测 15 秒超时）。此时应改用「卡片可见区域
  固定点位 + 目标面板状态自证」（`PATA_CARD_POS` + `_pata_panel_open` 检查任一塔的「出发」），
  而不是继续调阈值或在原地重试。
- **模板搜索区域**：`find_center` / `find_center_silent` / `wait_and_click` 支持
  `region`（整屏绝对坐标）与 `client_region`（客户区相对坐标，两者互斥）。底部导航 /
  底部页签这类位置固定的目标优先用 `common.BOTTOM_BAR_CLIENT_REGION`（按 1600×900
  取底部 250px，实测单次匹配 61→18ms）；**战斗页、结算页、弹窗、返回箭头必须保持
  全客户区**——限制区域漏判后会被误判成「已回主界面」，后续入口全部落空。

## 4. 每次点击都要「点 → 校验 → 必要时补点」

- 游戏不在前台时，系统会把**第一次点击用于激活窗口而吞掉**。`ensure_game_clickable`
  先激活，且激活后必须 `sleep(0.25)`——激活是异步的，不等就写坐标仍会被吞（实测复现）。
- **角落 HUD 图标上这条更狠**：实测点主界面左下角「目标」、右下角好友、右侧「世界」时，
  `twice=False` **完全没有任何反应**（不是偶尔丢一次），改 `twice=True` 立刻生效；
  而面板内的大按钮 `twice=False` 一直是好的。所以**按入口位置选点击方式**：
  角落 HUD 图标用连点两下 + 锚点确认 + 重试，跳转类按钮仍用单击（连点会「进完又退出」）。
  判据永远是「目标面板的锚点在不在」，不是「我点了」。
- 跳转类按钮（玩法目录入口、模式入口、`repeat(e)`、结果页返回）点击后**必须确认目标界面**：
  确认不到时，只在「仍停在原页面」的前提下补点一次；界面已经变化就**不要盲点**。
  参考 `push._enter_mode_and_confirm` / `push._click_repeat_and_confirm`。
- 「已进入某面板」的判据可靠性排序：
  1. 面板内**静态**锚点（不随子页/动画变的控件）；
  2. 对**多个未选中态**页签做或判断（面板会记住上次子页，选中态会换外观）；
  3. 上级判据：「主界面 HUD 是否消失」（`_is_at_main_interface`）。
  不要拿单个页签当唯一锚点，也不要拿半透明 HUD 文字标签当锚点。
- 领取类动作只认**结果信号**：弹出「获得奖励」/「点击空白处关闭」才算领到。
  点了没弹奖励就记入 dead_ends 不再重复点，否则会原地打转。
- **竞技场的多步跳转要按界面走，别按普竞的状态机硬套**：巅峰竞技场在「继续挑战」之后还有
  选择对手（三张卡，取最左最弱）→「挑战他!」→ 阵容页（默认第 1 队，底部按钮是「编辑下一场」，
  连点两次切到第 3 队后才变成「战斗」）→ 整场观战（**没有跳过**）→ 失败页 → 挑战界面。
  每一步都用对应标题模板自证（`dianfengxuanzeduishou` / `dianfengtiaozhan` /
  `dianfengbianji` / `dianfengzhandou`），不要拿普竞的 `zhandou` / `tiaoguo` 去等。

## 5. 检测器要用正样本验证，不能只看「0 命中」

「扫不到 = 干净」是最容易骗过自己的结论。本轮通用角标检测就是被这条推翻的：
同一屏肉眼有 5 个礼包角标，检测器返回 0。任何「找东西」的函数上线前，先在
**已知存在目标的那一屏**跑一次，断言它能命中并给出坐标；再做负样本（易混淆界面）。

同理，实跑结论要落到可核对的证据行：日志里的
「点击 repeat(e)(1) 后失败页仍在，重试点击 repeat(e)」比「已修复」有用。

### 5.1 静默动作的判据要选**单调变化**的量

没有弹窗、没有 OCR 时，只能靠「某区域点击前后自匹配掉分」判定动作生效。选错量会得出
**完全相反**的结论：翻翻乐的「点击增加进度」实测一次单击会连抽到本轮 100 满、进度随即**归零**，
所以盯进度数字会得到「点了没反应」（连点 3 次都停在 0/100），而盯钥匙余量立刻看出
265→219→119 的真实消耗。规则：**先问这个量会不会回到原值**——会归零/会循环的一律不能当判据，
要换成只增不减（或只减不增）的那个量，并在动手前用一次「不点击的静止双帧」量出噪声底。

**噪声底要在「刚进页面的过渡期」也量一次**，不能只量停稳后的。翻翻乐最初把阈值定在 0.97，
理由是静止自匹配 1.000；随后实测同一区域在页面切换动画期间就有 0.964–0.975，阈值正好落在
噪声带里，会把「页面还没停稳」误判成「动作生效」。判据阈值必须**低于观测到的最差噪声**，
而不是低于某一次好看 samples。

这套「动作前后区域是否变化」的判据已收口为 `common.region_changed_since()`（内部复用
`common.crops_differ()`）：比较与轮询等待只有一份实现，**区域与阈值仍由调用方注入**（不同界面
的噪声底不同，不能合并成一个全局数）。新调用点必须在注释里写下「静止 X / 真变化 Y」两个实测数。

**更狠的一种：信号本身比噪声还小**。月桂之旅内层「奖励/任务」页签行，实测静止噪声底
**0.992**、而真的切了页之后自匹配仍有 **0.989**——变化量小于噪声量，这个区域**根本不能当判据**，
再怎么调阈值都是随机漏扫。换区域重测才解决：子页签那一行静止 **1.000**、切页掉到 **-0.3**
（绿色选中胶囊横向移动，`TM_CCOEFF_NORMED` 直接负相关），余量三个数量级。
所以选判据区域的顺序是：**先量「静止 vs 真变化」两个数，差距不够大就换区域**，
而不是先定阈值再祈祷信号够强。

### 5.2 列表要滚动时，现点击链路做不到

`send_coord` 的 IPC 只传坐标、AHK 只做一次点击，**没有滚轮也没有拖拽**，所以玩法目录这类
需要滚动的长列表无法浏览到底（实测「钓鱼」的玩法本体在列表更下方，只能停在任务清单页）。
要么走有固定入口的短路径（如 翻翻乐 页右侧「本周焦点」缩略图），要么先给点击器加拖拽/滚轮能力。

## 6. 勘察未知界面的闭环

1. 单击候选位置 → 截图客户区 → 读图确认这是什么界面；
2. 需要新模板时：`crop` 到控件主体 → 在目标屏验证 ≥0.95、在最易混淆屏 ≤0.7、实点确认落点；
3. 模板装进 `templates/` 后立即 `pytest`（`tests/test_templates.py` 会校验所有
   `get_template_path("x.png")` 字面量引用的文件都存在）；
4. 弃用的模板**同时删文件**，不留孤儿（`CLAUDE.md` §3：自己改动产生的孤儿自己清）。

## 7. 门禁与「零新增」基线比对

- 每轮改动：`pwsh -NoProfile -File build.ps1 check`，一次跑完
  `compileall` → `pytest -q` → `ruff check .` 并按基线比对。
- **失败现场**：任务返回失败/超时或抛异常时，程序自动把最近 5 帧截图写到
  `debug/failures/<时间>_<任务名>/`（`frame_00.jpg…`、`client.jpg`、`meta.txt`），只保留最近 5 个现场；
  F9 主动停止不保存。排查「卡在哪一屏」时先看这里，再对照日志。
- lint 基线登记在仓库根的机器可读文件 `.ruff_baseline`（每行 `文件=条数`，全仓合计 64 条）。
  `build.ps1 check` 逐文件比对：**任何文件高于基线即失败并指名文件与新增条数**，低于基线视为改善。
  要判断某文件的告警是否出自本轮改动，仍逐文件与 HEAD 比：
  `git show HEAD:push.py | ruff check --stdin-filename push.py --output-format concise -`
- 测试要覆盖**新写的分支**而不是只跑通主路径：吞点击重试、离开原页面后不盲点、
  领取上限截断，都各有一条确定性单测（`tests/test_push_fail_limit.py`、
  `tests/test_hongbaolingqu.py`）。
- 新增用例要做**反向验证**：把改动临时改回旧写法跑一遍，用例必须失败。
  绿色用例不等于有效用例（日志落盘那条就是这样确认不是空跑的）。

## 8. 发布收尾链（顺序不能换）

1. 文档同步（README 功能表 / 项目结构、CHANGELOG 记结论与**撤销过的方案**）；
2. `git commit` → `GIT_TERMINAL_PROMPT=0 git -c credential.interactive=false push origin main`
   （本机 GCM 会卡 push，必须非交互）；
3. `pwsh -NoProfile -File build.ps1 build`；
4. **解包校验产物**，不要只看构建成功：
   ```python
   from PyInstaller.archive.readers import CArchiveReader
   a = CArchiveReader('goldenhandmaidens.exe')
   z = a.open_embedded_archive('PYZ.pyz')          # 模块是否打进去（函数内动态 import 也在）
   png = {n for n in a.toc if n.endswith('.png')}   # 模板路径是反斜杠 templates\xxx.png
   ```
5. 清 `%TEMP%` 会话残留 → `git status` 干净 → 把游戏带回主界面（若用户没关游戏）。

## 9. 副作用与账号成本（跑之前要意识到）

- 领取/推图会**真实消耗账号资源**（门票、扫荡次数、派遣），且不可回退。
- 盲点固定坐标可能误闯带**自动派遣倒计时**的活动页（实测误入「纷战争锋」），
  或触发生产/购买。任何「按栅格逐点」的写法都要先想清楚点空位会落到什么控件上。
- 流程末尾必须 `recover_to_main_interface()`，否则下一个任务从错误界面开始，
  表现成「上一任务把下一任务带崩」的假象。
- 日志文件 `game_bot.log` 按 **UTF-8** 写入（`append_log_file` 指定 `encoding="utf-8"`），
  读它也要 UTF-8；在 GBK 控制台里直接看会显示成乱码，那是终端的解码问题，不是文件坏了。
- **「日志会落盘」要按内容验证，不能只看文件在不在**：本轮 `game_bot.log` 一直存在且在写，
  但子脚本 `common.log()` 的细节行（哪张模板没命中、哪一项领到）一条都没进去——
  汇聚 sink 只接了面板。核对方式是拿**用户刚跑完的那一轮**去 grep 最有代表性的模块前缀
  （如 `【家园愿望单】`），搜不到就说明落盘链路有缺口。
- **测试不许写产品日志**：GUI 测试会构造 `GameBotGUI`，其 `__init__` 期的 `log()` 走的是
  模块级 `LOG_FILE`，早于用例自己打的补丁；三十轮 pytest 在用户的日志里堆了 300 行启动噪声，
  正好把要看的行埋掉。会话级夹具统一把 `bot_runtime.LOG_FILE` 指向临时目录。
