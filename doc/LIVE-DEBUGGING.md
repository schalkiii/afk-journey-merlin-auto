# 实机开发与调试方法学

本文只讲**怎么在这个项目上开发、调试、验证**：怎么在不动用户鼠标的前提下跑真实游戏、
怎么判定「真的进去了 / 真的领到了」、怎么收尾。模板本身的采集与标定规则见
[TEMPLATE-AUTHORING.md](TEMPLATE-AUTHORING.md)；行为约束见根目录 `CLAUDE.md`。

## 1. 前置条件（先确认，否则所有现象都会误诊）

- **点击器存活**：`common.clicker_alive()`（只读的 `tasklist` 进程查询，不写坐标文件、
  不产生任何真实点击；旧版用「哨兵坐标」探测会误点用户光标所在窗口，已废弃）。
  游戏《剑与远征：启程》以**管理员**运行，
  未提权进程的 `SendInput` / `PostMessage` / `PrintWindow` 会被 UIPI 拦截（实测
  PrintWindow ok=0、PostMessage=0）。点击走文件 IPC：Python 写
  `shared/target_coord.txt`（**整屏绝对坐标**）→ 提权的 `click_from_file.exe` 消费并注入。
  点击器自己退出后所有点击静默落空，表现是「界面连续多轮无变化」——先查它，再查逻辑。
- **后台点击做不了，别在这上面浪费时间**：实测对本作 Unity 客户端，`PostMessage` /
  `SendMessage`（含 `WM_ACTIVATE` / `WM_SETFOCUS` 预热）都返回成功但界面毫无变化；
  给窗口加 `WS_EX_NOACTIVATE` 后在非前台状态发真实点击也不生效。它只接受真实前台输入，
  所以「完全不抢鼠标」不可实现；能做的只有每次点击后把光标放回原处
  （`common.send_coord` 的默认行为），窗口激活瞬间无法避免。
- **截图通路**：默认 Windows Graphics Capture（`windows-capture`），能截被遮挡/提权窗口；
  不可用时回退普通屏幕截图。截图坐标系始终是**全屏**，`find_center*` 返回值也是全屏坐标。
- **客户区必须 1600×900**：`game_client_region()` 每次调用都重新校验；不是这个尺寸
  整套模板与偏移全部失效，GUI 启动任务时会打警告。RDP 断连/锁屏时系统停止渲染，
  后台截图拿不到新帧——保持会话连接。
- **注入器与游戏必须同会话**（2026-11-12 冷启动真因）：坐标文件被消费**不代表**点击生效，
  跨会话时注入器会把点击打到另一个桌面。`common.clicker_session_mismatch()` 查一次即可；
  详见 §5.3。
- **调试脚本必须提权跑**（同日第二次踩，代价是半小时）：用普通权限的 python 起 GUI，
  注入器继承普通权限，`SendInput` 被 UIPI 拦死。表现和「注入器死了」一模一样——
  坐标文件照常被消费、日志一句不报、界面 8 轮无变化后判卡死。核对方法：

  ```bash
  python -c "import common; print(common.is_process_elevated())"   # 必须 True
  ```

  以管理员跑：

  ```powershell
  Start-Process -Verb RunAs -FilePath <python.exe> -ArgumentList '<script.py>' -WorkingDirectory <repo>
  ```

  代价：提权进程**无法用普通权限 `Stop-Process` 结束**，要再提权 `taskkill /F /PID`。
  打包出的 exe 已在 spec 里 `uac_admin=True`，双击即提权；直接跑源码调试时自己提权。

## 2. 怎么发起一次实跑（不碰用户鼠标）

用户明确不要用桌面自动化挪鼠标，所以实跑一律走进程，两种形态：

1. **走 GUI（验证真实用户路径）**：临时脚本实例化 `GameBotGUI` →
   `select_script(idx)` → `root.after(2500, app.run_single_script)` →
   `root.after(120, app._drain_log_queue)` → `mainloop()`。
2. **直调流程（验证单个状态机）**：临时脚本 `import flow_push; flow_push.main(...)`。

   注意：各模块自带的 `if __name__ == "__main__": main()` **不注入 F9 停止检查，也不接日志汇聚**，
   直接 `python <module>.py` 会真实驱动点击链路且无法即时中断。单文件直调只用于离线验证
   决策逻辑（配合打桩），**不得用于账号操作**；要实跑一律走上面两种形态或 GUI。

3. **冷启动全链路（游戏关闭 → 定时拉起 → 登录 → flow）**：验证的是「没人管也能自己跑起来」，
   和上面两种的区别是**游戏进程从零开始**，因此必须先把游戏关干净再计时。

   ```python
   # 临时脚本，放 %TEMP%；GUI 里只剩定时这一条路，才是在测真实链路
   root = tk.Tk(); app = gh.GameBotGUI(root)
   target = datetime.now().astimezone() + timedelta(minutes=2)
   app.schedule_hour_var.set(target.hour); app.schedule_min_var.set(target.minute)
   app.set_schedule()                     # 走真实定时，不要直接调 _fire_schedule
   root.after(8 * 60 * 1000, watchdog)    # 到点后 stop_all + destroy
   root.mainloop()
   ```

   - 关游戏要**提权**（游戏以管理员运行）：`Start-Process -Verb RunAs taskkill.exe -ArgumentList '/PID','<pid>','/F' -Wait`，
     普通 `Stop-Process` 会「拒绝访问」。PID 从 `find_game_window()` + `GetWindowThreadProcessId` 取。
   - 开跑前记 `wc -l game_bot.log`，跑完只读新增段（`tail -n +<基线>`），否则会混进历史轮次。
   - 判据不是「有没有日志」，而是**关键动作只出现一次**：
     `grep -c "定时开始时间到，启动游戏并运行脚本"` 在新增段里必须是 1。
     两次说明定时线程泄漏了两条循环（见 `_schedule_gen` / `FIRE_GUARD_SECONDS`）。
   - 冷启动时间量级（2026-11-12 实测）：快捷方式拉起 0.4s → 就绪（界面标志）约 19s →
     登录到主界面约 40s。任何「按固定秒数就开始跑任务」的写法都会在这里翻车，所以要等**模板标志**。

共同纪律：

- 用 `pwsh -NoProfile -Command "Start-Process ... -PassThru | Select-Object -ExpandProperty Id"`
  **分离启动并拿 PID**，不要在前台阻塞等待。
- runner 里把 stdout/stderr tee 到 `%TEMP%` 的日志文件并**每行 flush**，
  之后用短命令轮询 `tail -c`；不要 `sleep` 很久再一次性读。
- 结束用 `taskkill //F //PID <pid> //T`（连子进程树），并确认没有孤儿 `python` 留下。
  判别归属看进程 `StartTime`：本轮的 PID 与用户长期存在的进程要分得清。
- 临时脚本与截图**写在 `%TEMP%`，不落在仓库根目录**；用完即删。

## 3. 坐标纪律

- `send_coord` / `click_position` 收的是**整屏绝对坐标**。调试脚本若按客户区坐标点
  （如 `x=100, y=35`）必须加 `game_client_region()` 原点再传，否则点到别处——
  本轮就因这个 bug 把「点击没生效」误判成游戏问题。
- 客户区固定 1600×900 时，允许「固定点位点击」，但**必须带进入校验**（见 §4），
  且把点位写成带注释的常量（如 `PATA_CARD_POS = (625, 700)`），不要散落魔法数。
  点位只能来自实机截图实测：右侧 HUD 竖排 `(1550,610)` 看起来像「月桂之旅」入口，
  实测点完只落在主界面，真入口在菜单第二行第 4 张卡片 `LAUREL_MENU_POS = (905, 625)`。
- **模板一直等不到时，先怀疑遮挡而不是阈值**：玩法目录第三行卡片的卡名被底部页签栏压住，
  同一张 `pata.png` 无论阈值调到多低都匹配不到（实测 15 秒超时）。此时应改用「卡片可见区域
  固定点位 + 目标面板状态自证」（`PATA_CARD_POS` + `_pata_panel_open` 检查任一塔的「出发」），
  而不是继续调阈值或在原地重试。
- **模板搜索区域**：`find_center` / `find_center_silent` / `wait_and_click` 支持
  `region`（整屏绝对坐标）与 `client_region`（客户区相对坐标，两者互斥）。底部导航 /
  底部页签这类位置固定的目标优先用 `common.BOTTOM_BAR_CLIENT_REGION`（按 1600×900
  取底部 250px，实测单次匹配 61→18ms）；**战斗页、结算页、弹窗、返回箭头必须保持
  全客户区**——限制区域漏判后会被误判成「已回主界面」，后续入口全部落空。

## 4. 每次点击都要「点 → 校验 → 必要时补点」

- 游戏不在前台时，系统会把**第一次点击用于激活窗口而吞掉**。`ensure_game_clickable`
  先激活；但**激活必须被确认而不是盲等**——2026-11-11 的教训是旧实现
  `SetForegroundWindow` 后 `sleep(0.25)` 就当成功，而在前台锁下该调用会**静默失败**，
  于是当天从第一个「邮件」任务起每次点菜单都被吞。现在它返回三态（True 已确认在前台 /
  False 前台锁没解开 / None 未启用或取不到窗口）并轮询 1 秒确认 `GetForegroundWindow`；
  拿到 False 时 `send_coord` 会先 `_click_title_bar()` 用一次标题栏点击完成激活——
  标题栏在客户区之外，点它不会触发任何游戏内操作（本机实测：窗口上边界 45、客户区上边界 76，
  标题栏高 31px，`title_h < 12` 时判为无标题栏并放弃）。
- **角落 HUD 图标上这条更狠**：实测点主界面左下角「目标」、右下角好友、右侧「世界」时，
  `twice=False` **完全没有任何反应**（不是偶尔丢一次），改 `twice=True` 立刻生效；
  而面板内的大按钮 `twice=False` 一直是好的。所以**按入口位置选点击方式**：
  角落 HUD 图标用连点两下 + 锚点确认 + 重试，跳转类按钮仍用单击（连点会「进完又退出」）。
  判据永远是「目标面板的锚点在不在」，不是「我点了」。
- 跳转类按钮（玩法目录入口、模式入口、`repeat(e)`、结果页返回）点击后**必须确认目标界面**：
  确认不到时，只在「仍停在原页面」的前提下补点一次；界面已经变化就**不要盲点**。
  参考 `push._enter_mode_and_confirm` / `push._click_repeat_and_confirm`。
- 「已进入某面板」的判据可靠性排序：
  1. 面板内**静态**锚点（不随子页/动画变的控件）；
  2. 对**多个未选中态**页签做或判断（面板会记住上次子页，选中态会换外观）；
  3. 上级判据：「主界面 HUD 是否消失」（`_is_at_main_interface`）。
  不要拿单个页签当唯一锚点，也不要拿半透明 HUD 文字标签当锚点。
- 领取类动作只认**结果信号**：弹出「获得奖励」/「点击空白处关闭」才算领到。
  点了没弹奖励就记入 dead_ends 不再重复点，否则会原地打转。
- **竞技场的多步跳转要按界面走，别按普竞的状态机硬套**：巅峰竞技场在「继续挑战」之后还有
  选择对手（三张卡，取最左最弱）→「挑战他!」→ 阵容页（默认第 1 队，底部按钮是「编辑下一场」，
  连点两次切到第 3 队后才变成「战斗」，实测加载 2~3 秒、偶发更久）→ 战斗（**有「跳过」按钮**，
  客户区约 (1090,712)，点了直接出结算）→ 失败页 → 挑战界面。
  每一步都用对应标题模板自证（`dianfengxuanzeduishou` / `dianfengtiaozhan` /
  `dianfengbianji` / `dianfengzhandou`），不要拿普竞的 `zhandou` / `tiaoguo` 去等。
- **全屏弹窗会「部分遮挡」**：入场时压着的「每日结算」大弹窗，遮罩下底部绿色长条仍能匹配到，
  但点击会被遮罩吞掉。遇到「模板命中却点不动」先怀疑弹窗遮罩：用弹窗**标题**模板确认存在
  （无标题就不点），再点弹窗外的固定空白点。失败页同理会误判——通用「点击空白处关闭」模板在
  失败页只有 0.41 分，改用已验证避开所有按钮的固定空白点（巅峰竞技场用客户区 (1300,200)）。
- **入口点击必须自证**：2026-11-07 实机同一坐标第一次点击常被窗口激活吞掉，日志表现为
  「命中 玩法目录」之后卡片 8~15 秒全部匹配不到。点完入口用目录标题（`wanfamulubiaoti`）
  确认，未出现补点一次，见 `common.open_wanfamulu()`。
- **面板会记住上次子页**：巅峰竞技场重新进入可能落在商店/排行榜/战斗记录/巅峰联赛，
  「继续挑战」不出现；点左下返回箭头即回挑战主页（实测返回后按钮 0.92）。
- **弹窗类按钮必须单击**：愿望单进度礼盒用连点会把刚弹出的「获得奖励」当场关掉，
  表现为奖励已发但流程判未领；领奖一律单击 + 轮询弹窗。
- **没有返回入口的界面只能避免进入**：家园「制造工艺」配方页点面板外空白/保存都退不出来；
  补货时只能在仍处于家园视图时点角色脚下交互提示，进入生产界面后不要再点产品卡片。
- **战斗结束信号会变**：迷梦之域实测结束后直接回主界面、不弹「竞技场结算」；
  等结算前先接受「挑战按钮重新可见」这一信号。
- **卡片消失时不要盲点固定点位**：2026-11-07 常规玩法页已移除「天穹试炼」，旧的固定兜底
  会点到相邻卡片（女神试炼/巅峰竞技场）并把游戏带进别的玩法页；模板不存在就记录并跳过。
- **「点了没进去」会一路错下去，所以要用原语而不是各写一遍**：2026-11-10 一天内的失败几乎
  同构——点塔卡片被吞 → 当成已进入 → 塔内按钮 15 秒等不到 → 误判「已经推完」→ 点 `exit`
  把玩法目录关掉 → 后续全崩。跳转型点击统一走 `common.click_and_confirm(tpl, name, confirm)`：
  点一下 → 轮询 confirm → 没生效才补点（最多 N 轮）。**别用 `twice=True` 代替**，连点会
  「进入后又退出」。
- **confirm 判据的三条硬要求**：① 选目标页面**独有**的元素（塔页的挑战/扫荡按钮）；
  ② 不要用「当前页面元素消失」当唯一判据（加载动画期间两边都不成立）；③ `is_loading_screen()`
  为真时直接判 False，等加载结束再确认。②的反面教材：进塔曾用 `_left_catalog_page`（只判
  「`玩法目录` 标题消失」）确认，而**塔选择页同样没有这个标题**，点塔被吞也判通过；现已改为
  `pata._in_tower_page()`（塔内独有的「爬塔挑战」按钮）。对比实现见
  `nvshenta._tower_page_open`。
- **没有「点击空白处关闭」提示的遮挡面板**：点「挑战」后弹出的「已达成玩家」赛季进度榜单
  会整屏盖住备战界面，等 10 秒就被误判「无法进入模式」。该面板左下角是个普通返回箭头
  （`exit.png` 实测 0.983），可以点它关闭——但**必须加误点保护**：只有在
  `autocha` 与 `guajijixian` 都不可见时才点，否则会把正常备战界面/门票弹窗退掉。
  见 `push._clear_occluder()`。
- **同一个模板跨状态复用会掉分**：`fanfanle.png` 只有 45×16，是从某个页签背景裁的小图；
  面板停在别的页签（未选中态）时匹配只有 0.72、选中态反而 0.93。小模板必须**按状态各采一套**，
  并在实机上量两个状态的分数，不能靠一个阈值硬扛。
- **复用点击注入器前必须自证**：2026-11-11 的「点击都不准」还有第二条根因——GUI 只判断
  「有 AHK 进程在跑」就复用，而当时复用的是前一天启动的进程，`workDir` 未必指向当前仓库
  （例如已被清理的 `_MEI` 临时目录），坐标写在本目录就无人消费。复用前先用一次
  `_click_title_bar()` 自证「能消费本目录坐标」，不行就重启注入器并显式传入 `workDir`。
- **「标题匹配不到」不等于「点击被吞」**：全屏结算弹窗会把底下面板压暗（实测标题掉到 0.35）。
  若把「面板标题可见」当作点击生效的唯一判据，成功的动作会被判成失败，随后对着旧坐标补点
  反而把面板点没（狩猎悬赏实测）。判据要写成「动作有反馈」：标题可见 **或** 结算弹窗可见，
  两者都不成立才算被吞。
- **一次点不动先重试再下结论**：翻翻乐一轮点完有翻牌演出，演出期间点击不生效；旧逻辑把
  「点了没变化」直接当「钥匙用完」，实机核对发现钥匙还剩 376 把。凡是「无变化即结束」的循环，
  都必须**重试若干次**（此处 `CLICK_RETRIES=3`）并在每轮开始前等演出停稳再取基准帧。
- **领奖跳转会改变界面，时序要看清**：推图的首通奖励要跳「赛季阶段排名 → 首通」再原路退回，
  回来时已不是备战页；把它放在「进入模式成功」之后，就会用陈旧的状态判据做事。而且它的
  入口（右上角奖杯）**只在推图主界面存在**，进了备战页两次点击都打不开。结论：
  领奖步骤要么放在进入子页面之前，要么领完重新判定当前界面。

## 5. 检测器要用正样本验证，不能只看「0 命中」

「扫不到 = 干净」是最容易骗过自己的结论。本轮通用角标检测就是被这条推翻的：
同一屏肉眼有 5 个礼包角标，检测器返回 0。任何「找东西」的函数上线前，先在
**已知存在目标的那一屏**跑一次，断言它能命中并给出坐标；再做负样本（易混淆界面）。

同理，实跑结论要落到可核对的证据行：日志里的
「点击 repeat(e)(1) 后失败页仍在，重试点击 repeat(e)」比「已修复」有用。

### 5.1 静默动作的判据要选**单调变化**的量

没有弹窗、没有 OCR 时，只能靠「某区域点击前后自匹配掉分」判定动作生效。选错量会得出
**完全相反**的结论：翻翻乐的「点击增加进度」实测一次单击会连抽到本轮 100 满、进度随即**归零**，
所以盯进度数字会得到「点了没反应」（连点 3 次都停在 0/100），而盯钥匙余量立刻看出
265→219→119 的真实消耗。规则：**先问这个量会不会回到原值**——会归零/会循环的一律不能当判据，
要换成只增不减（或只减不增）的那个量，并在动手前用一次「不点击的静止双帧」量出噪声底。

**噪声底要在「刚进页面的过渡期」也量一次**，不能只量停稳后的。翻翻乐最初把阈值定在 0.97，
理由是静止自匹配 1.000；随后实测同一区域在页面切换动画期间就有 0.964–0.975，阈值正好落在
噪声带里，会把「页面还没停稳」误判成「动作生效」。判据阈值必须**低于观测到的最差噪声**，
而不是低于某一次好看 samples。

这套「动作前后区域是否变化」的判据已收口为 `common.region_changed_since()`（内部复用
`common.crops_differ()`）：比较与轮询等待只有一份实现，**区域与阈值仍由调用方注入**（不同界面
的噪声底不同，不能合并成一个全局数）。新调用点必须在注释里写下「静止 X / 真变化 Y」两个实测数。

**更狠的一种：信号本身比噪声还小**。月桂之旅内层「奖励/任务」页签行，实测静止噪声底
**0.992**、而真的切了页之后自匹配仍有 **0.989**——变化量小于噪声量，这个区域**根本不能当判据**，
再怎么调阈值都是随机漏扫。换区域重测才解决：子页签那一行静止 **1.000**、切页掉到 **-0.3**
（绿色选中胶囊横向移动，`TM_CCOEFF_NORMED` 直接负相关），余量三个数量级。
所以选判据区域的顺序是：**先量「静止 vs 真变化」两个数，差距不够大就换区域**，
而不是先定阈值再祈祷信号够强。

**只盯一个区域同样会漏判**。2026-11-10 实机：翻翻乐钥匙 157 → 0 全烧完了，脚本每一轮却都
报「钥匙余量未变化」并提前收工。原因是判据只覆盖「当前剩余」这一行——页签切换动画、数字
滚动、结算演出都可能让那一行整段落在过渡帧上。改成「钥匙余量」**或**「累计进度」任一区域
变化即算推进（`PROGRESS_REGION`），超时也从 3 秒提到 6 秒覆盖一期翻牌演出。规则：静默动作的
判据用**多个单调量取或**，单点判据迟早会在某个动画阶段失灵。

### 5.2 列表滚动：用逐步拖动，不是瞬移式

2026-11-08 实测打通：`common._drag_scroll()` 用 SendInput **逐步拖动**（按住左键 → 25 步
移动 → 松开，try/finally 保证松开），能触发 Unity ScrollRect 滚动；AHK 的 `send_drag`
是瞬移式（按下→瞬间跳到终点→松开），ScrollRect 不认。滚轮（mouse_event / SendInput）
能滚，但滚到底后底部页签栏会遮挡列表末尾标题、模板匹配不到，所以要靠拖动把内容拖到
标题露出再点。拖动列用**第一张卡片的 x**（卡片间隙上 ScrollRect 也不认）。

`common.scroll_in_client_region()` 封装了这套：默认按玩法目录卡片列表比例取滚动区，
传 `region=(x, y, w, h)` 可滚动悬赏卡片网格等其它列表。**不能点卡片图案区**——按钮在
标题区，必须拖到标题可见再点（玩法目录第三行卡片标题被页签栏遮挡时模板匹配不到）。

**滚动依赖管理员权限**：`_drag_scroll` 用 SendInput，目标窗口是管理员进程时，普通权限的
Python 发出去会被 UIPI 静默拦截——现象是「滚了 3 次列表纹丝不动」，前后帧相似度 0.999，
`pata` 随后报「滚动后仍未找到天穹试炼卡片」。用非提权的 `py` 手动调脚本时必然复现；
正式 exe 以管理员运行才正常。诊断时先打印 `ctypes.windll.shell32.IsUserAnAdmin()`，
别把它当成模板或坐标问题。

### 5.3 注入器必须和游戏在**同一个 Windows 会话**

2026-11-12 冷启动实测踩到：注入器是上一个 RDP 会话（`RDP-Tcp#1`，session 3）启动后留下的，
而游戏在 `Console`（session 1）。表现极具欺骗性——坐标文件被正常读走（所以
「文件消失 == 点击完成」的判据成立、`_click_title_bar()` 自证也过），但 `SendInput` 打在
另一个会话的桌面上，游戏画面一动不动。

**判据只能是比较会话号**，不能看坐标文件是否被消费：

```python
common.game_window_session_id()      # GetWindowThreadProcessId → ProcessIdToSessionId
common.clicker_session_mismatch()    # None = 一致；否则返回可读说明
```

处理方式：清掉旧注入器（`taskkill /IM AutoHotkey64.exe`）并在**当前会话**重启。
GUI 的复用判定已内置这条；`send_coord` 首次调用会记一条告警。多会话环境（RDP Wrapper、
向日葵、远程协助）里尤其要先查这一条。

**「关掉工具」不等于「关掉注入器」——这是残留的真正来源。** 注入器是独立进程，
工具退出时若没显式回收，它会一直活着（并一直守着自己启动时所在会话的桌面）。
2026-11-12 的实证：`on_closing` 只 `taskkill /IM click_from_file.exe`，而装了 AHK v2 的
机器上注入器进程名是 `AutoHotkey64.exe`，**按名字根本杀不到**；一条 session 3 的注入器
因此活了整整一天，期间所有点击都「消费坐标但游戏不动」。

三条纪律：

1. **按 PID 回收，不按名字猜**：启动时记 `Popen.pid`，退出时 `taskkill /F /T /PID <pid>`；
   名字只做兜底（`click_from_file.exe` 一定是自己的，`AutoHotkey64.exe` 可能不是）。
2. **杀之前校验镜像名**：PID 会被系统复用，照 PID 盲杀可能打到无关进程。
3. **杀不掉必须留痕**：提权启动的注入器，普通权限 `taskkill` 报「拒绝访问」。
   静默失败最危险——下次启动会以为「已有注入器可用」而复用它。
   日志里出现「无法结束注入器 PID …（可能以管理员权限运行）」，就要手动清，
   而且清理本身也得提权（`Start-Process -Verb RunAs taskkill.exe /F /PID <pid>`）。

排查现况（看数量与所在会话）：

```bash
tasklist /FO CSV /NH | findstr /I "autohotkey click_from"   # 有没有、在哪个会话
```

### 5.4 「等某个东西出现」的循环必须有**无进展上限**

2026-11-12：巅峰竞技场点完「跳过」后，界面既不是失败页、也不是挑战主页、也没有
「点击空白处关闭」。旧循环每 5 秒只做一件事——重判那两个模板，命不中就继续等，
于是 36 轮（180 秒）纯空转，用户看到的就是「显示完成但中途卡住」。

两条硬要求：

1. **每一轮都要能做出实质动作**：按钮还在就补点、命中弹窗就关、加载中就等；
2. **连续 N 轮什么都没做成 → 提前放弃并保存失败现场**（`capture_failure_context`），
   不要靠外层大超时兜底。大超时只该保护「确实在推进但很慢」的情况。

轮询函数另加 `quiet=True`：每轮超时都打一行「放弃等待」会把日志刷成连续同质墙，
把真正的信号（哪一轮做了补救）埋掉。

## 6. 勘察未知界面的闭环

1. 单击候选位置 → 截图客户区 → 读图确认这是什么界面；
2. 需要新模板时：`crop` 到控件主体 → 在目标屏验证 ≥0.95、在最易混淆屏 ≤0.7、实点确认落点；
3. 模板装进 `templates/` 后立即 `pytest`（`tests/test_templates.py` 会校验所有
   `get_template_path("x.png")` 字面量引用的文件都存在）；
4. 弃用的模板**同时删文件**，不留孤儿（`CLAUDE.md` §3：自己改动产生的孤儿自己清）。

## 7. 门禁与「零新增」基线比对

- 每轮改动：`pwsh -NoProfile -File build.ps1 check`，一次跑完
  `compileall` → `pytest -q` → `ruff check .` 并按基线比对。
- **失败现场**：任务返回失败/超时或抛异常时，程序自动把最近 5 帧截图写到
  `debug/failures/<时间>_<任务名>/`（`frame_00.jpg…`、`client.jpg`、`meta.txt`），只保留最近 5 个现场；
  F9 主动停止不保存。排查「卡在哪一屏」时先看这里，再对照日志。
- lint 基线登记在仓库根的机器可读文件 `.ruff_baseline`（每行 `文件=条数`）。
  2026-11-07 已清零全部可安全修复的存量，**当前全仓 5 条**，均为有意保留的 catch-all
  （`Goldenhandmaidens.py=3`、`pata.py=2`，原因写在基线文件头）。
  `build.ps1 check` 逐文件比对：**任何文件高于基线即失败并指名文件与新增条数**，低于基线视为改善。
  要判断某文件的告警是否出自本轮改动，仍逐文件与 HEAD 比：
  `git show HEAD:push.py | ruff check --stdin-filename push.py --output-format concise -`
- 测试要覆盖**新写的分支**而不是只跑通主路径：吞点击重试、离开原页面后不盲点、
  领取上限截断，都各有一条确定性单测（`tests/test_push_fail_limit.py`、
  `tests/test_hongbaolingqu.py`）。
- 新增用例要做**反向验证**：把改动临时改回旧写法跑一遍，用例必须失败。
  绿色用例不等于有效用例（日志落盘那条就是这样确认不是空跑的）。
  每个测试文件的模块 docstring 都写有「负验证留痕」——列明改坏哪一处、哪条用例会变红；
  新增或改动用例时同步更新该清单，让「绿色是否有效」可核对。
  全仓用例不得出现无 `assert` / `pytest.raises` 的空跑用例（当前 305 条均有断言）。

## 8. 发布收尾链（顺序不能换）

1. 文档同步（README 功能表 / 项目结构、CHANGELOG 记结论与**撤销过的方案**）；
2. `git commit` → `GIT_TERMINAL_PROMPT=0 git -c credential.interactive=false push origin main`
   （本机 GCM 会卡 push，必须非交互）；
3. `pwsh -NoProfile -File build.ps1 build`；
4. **解包校验产物**，不要只看构建成功：

   ```python
   from PyInstaller.archive.readers import CArchiveReader
   a = CArchiveReader('goldenhandmaidens.exe')
   z = a.open_embedded_archive('PYZ.pyz')          # 模块是否打进去（函数内动态 import 也在）
   png = {n for n in a.toc if n.endswith('.png')}   # 模板路径是反斜杠 templates\xxx.png
   ```

5. 清 `%TEMP%` 会话残留 → `git status` 干净 → 把游戏带回主界面（若用户没关游戏）。

## 9. 副作用与账号成本（跑之前要意识到）

- 领取/推图会**真实消耗账号资源**（门票、扫荡次数、派遣），且不可回退。
- 盲点固定坐标可能误闯带**自动派遣倒计时**的活动页（实测误入「纷战争锋」），
  或触发生产/购买。任何「按栅格逐点」的写法都要先想清楚点空位会落到什么控件上。
- 流程末尾必须 `recover_to_main_interface()`，否则下一个任务从错误界面开始，
  表现成「上一任务把下一任务带崩」的假象。
- 日志文件 `game_bot.log` 按 **UTF-8** 写入（`append_log_file` 指定 `encoding="utf-8"`），
  读它也要 UTF-8；在 GBK 控制台里直接看会显示成乱码，那是终端的解码问题，不是文件坏了。
- **「日志会落盘」要按内容验证，不能只看文件在不在**：本轮 `game_bot.log` 一直存在且在写，
  但子脚本 `common.log()` 的细节行（哪张模板没命中、哪一项领到）一条都没进去——
  汇聚 sink 只接了面板。核对方式是拿**用户刚跑完的那一轮**去 grep 最有代表性的模块前缀
  （如 `【家园愿望单】`），搜不到就说明落盘链路有缺口。
- **测试不许写产品日志**：GUI 测试会构造 `GameBotGUI`，其 `__init__` 期的 `log()` 走的是
  模块级 `LOG_FILE`，早于用例自己打的补丁；三十轮 pytest 在用户的日志里堆了 300 行启动噪声，
  正好把要看的行埋掉。会话级夹具统一把 `bot_runtime.LOG_FILE` 指向临时目录。
